# 岡部エリオット（自前サーバー版）

Difyを使わず、LINE Messaging APIとOpenAI APIを直接呼び出す構成に作り直したバージョンです。
Difyの「AIクレジット」は一切消費しません。かかる費用はホスティング代（Render無料枠なら0円）と、
OpenAI APIの従量課金（実際に使った分だけ）のみです。

## Dify版との違い・改善点

- **クレジット制度なし** — OpenAIに直接、使った分だけ支払う従量課金です。
- **メンション検知が正確** — Difyでは「文中に@が含まれるか」で判定する近似的な方法でしたが、
  こちらはLINEのWebhookが送ってくる `mention.mentionees` の `isSelf` フラグを見て判定するので、
  「自分（Bot）宛てかどうか」を確実に判定できます。
- **既読（開封確認）に対応** — メッセージを受け取るたびに `markAsRead` APIを呼び、既読を付けます。
- **画像にも反応** — 送られてきた画像をVision対応モデルにそのまま渡して反応します。
- **他の人宛てのメッセージには本当に無反応** — Difyでは「応答は空にできない」という制約があり
  半角スペース1文字を返す形でしたが、こちらは何も送信しない、という形にできます。

## 事前に必要なもの（ご自身でご用意ください）

私（Claude）はアカウント作成やお支払い情報の入力を代行できないため、以下はご本人の作業になります。

1. **GitHubアカウント** — このコードを置く場所として使います（無料）。
2. **Renderアカウント**（https://render.com） — このサーバーを動かすホスティング先（無料枠あり）。
   他のホスティング先（Fly.io、Railwayなど）でも動きます。
3. **OpenAIアカウント + APIキー**（https://platform.openai.com） — 支払い方法の登録とAPIキーの発行が必要です。
4. 既存の **LINE Developersコンソール** のチャネルシークレット・チャネルアクセストークン
   （今までDifyのLINE Connectプラグインに入力していたものと同じ値です）。

## セットアップ手順

### 1. コードをGitHubにアップロード

このフォルダの中身をご自身のGitHubリポジトリにpushしてください（`.env`はコミットしないよう
`.gitignore`で除外済みです）。

### 2. Renderにデプロイ

1. Renderにログインし、「New +」→「Web Service」を選択
2. 先ほどのGitHubリポジトリを連携
3. 以下を設定
   - Build Command: `npm install`
   - Start Command: `npm start`
   - Instance Type: Free でOK（後述の制限あり）
4. 「Environment」タブで、`.env.example` にある4つの変数を登録
   （`LINE_CHANNEL_SECRET` / `LINE_CHANNEL_ACCESS_TOKEN` / `OPENAI_API_KEY` / `OPENAI_MODEL`）
5. デプロイすると `https://xxxxx.onrender.com` のようなURLが発行されます

### 3. LINE DevelopersコンソールでWebhook URLを切り替え

1. 対象チャネルの「Messaging API設定」を開く
2. 「Webhook URL」を `https://xxxxx.onrender.com/webhook`（上で発行されたURL＋`/webhook`）に変更
3. 「検証」ボタンで成功することを確認
4. 「Webhookの利用」がONになっていることを確認
5. これまでDifyのLINE ConnectプラグインのURLが設定されていた場合は、
   二重に反応しないよう、そちらは無効化（Webhook URLを空にするか、プラグイン自体を停止）してください

### 4. 動作確認

グループにLINEでメッセージを送ってみて、返信が来るか確認してください。
Render無料枠の場合、しばらくアクセスがないとサーバーがスリープするため、
スリープ明けの最初のメッセージは反応まで30〜60秒ほどかかることがあります
（以前Difyでも似たような遅延がありましたが、それと同じイメージです）。

### 5. メンバーのキャラクター学習機能をセットアップ（任意）

グループの各メンバーの話し方・キャラクターを覚えて、「〇〇のマネして」に対応できるようにする
機能です。使わない場合はこの手順は不要です（未設定でもエラーにはならず、単に機能が無効になるだけです）。

1. [Supabase](https://supabase.com) で無料アカウントを作成し、新しいプロジェクトを作成
2. プロジェクトのダッシュボードで「SQL Editor」を開き、`supabase_setup.sql` の中身を
   すべて貼り付けて実行（テーブルが2つ作られます）
3. 「Settings」→「API」を開き、以下をメモ
   - Project URL → `SUPABASE_URL`
   - `service_role` キー（`anon` キーではない方）→ `SUPABASE_SERVICE_KEY`
4. Renderの「Environment」タブに、上記2つの環境変数を追加してデプロイし直す

これでグループでの発言が少したまるごとに（8件ごと）、OpenAIがその人の話し方の特徴を
3〜4文で要約してSupabaseに保存するようになります。「エリオット、〇〇のマネして」のように
話しかけると、そのプロフィールを参考にして返事をしてくれます。

## 制限事項（正直にお伝えします）

- **直近の会話メモリはサーバーのメモリ上のみ**：サーバーが再起動（スリープからの復帰など）すると、
  直前までの会話の流れは忘れます。
- **メンバーのキャラクター・プロフィールはSupabase（DB）に保存**：こちらはサーバーが再起動しても
  消えません。ただし、要約に使った生の発言ログ自体はプライバシーに配慮して要約後に削除しており、
  残るのは「〇〇さんはこんな話し方をする」という3〜4文の要約だけです。
- **Render無料枠はスリープする**：15分アクセスがないとサーバーが停止し、次のメッセージで
  再起動するため遅延が発生します。常時起動させたい場合はFly.io（月4ドル程度〜）や
  Renderの有料プラン（月7ドル〜）への切り替えをご検討ください。
- **OpenAI APIの費用は別途発生**：Difyの「クレジット」はなくなりますが、OpenAI側に
  実際のトークン使用量に応じた料金が発生します（少人数のグループチャットであれば、
  月間で数ドル程度に収まることが多いです）。プロフィール要約も追加でOpenAIを呼び出すため、
  ごくわずかに費用が増えます。
- **キャラクター学習は本人の許可を得てから使うのがおすすめです**：グループのメンバーの発言内容を
  もとに特徴を記録する機能なので、事前にグループ内で一言共有しておくと安心です。

## ファイル構成

- `server.js` — 本体（Webhook受信・署名検証・既読・反応判定・OpenAI呼び出し・返信・メンバー学習）
- `package.json` — 依存パッケージ定義
- `.env.example` — 必要な環境変数の一覧（コピーして`.env`として使うか、Render側に直接登録）
- `supabase_setup.sql` — メンバーのキャラクター学習機能用のテーブル作成SQL（任意機能）
